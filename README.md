# エオルゼア釣り図鑑 — Eorzean Fish Guide

どの釣り場で、いつ、何が、どのエサで釣れるのか。
FF14Angler（猫はお腹がすいた）が埋めていた穴を、いま入手できるオープンデータで埋め直したもの。

**収録：釣り場 580（うち銛 64）／魚 2,620 種（うち 1,110 種は時間帯・天候・エサ・引きまで判明）**
**ヌシ 335 匹（うちオオヌシ 34 匹）の次回釣り日時を、実時間で計算**
**ヒットタイムの実測 9,934 件（328 釣り場）— 撒き餌あり／なし別のレンジ・分布・釣果率**

---

## 動かす

```bash
node tools/import-bite-times.mjs   # ヒットタイムの実測を取り込む（初回のみでよい）
node tools/build.mjs               # dist/ を生成
```

生成物は `dist/` に入る。静的ファイルだけなので、そのまま置けばどこでも動く。

```
dist/
  index.html            骨格だけ。80 KB
  data/core.xxxx.json   釣り場・魚・天候・運行表。1.6 MB
  data/bite.xxxx.json   ヒットタイム。1.2 MB（後追いで読む）
  standalone.html       全部入りの単体版。2.9 MB
  robots.txt / sitemap.xml / _headers / .nojekyll
```

**手元で確認するとき**は `dist/standalone.html` をブラウザで直接開く。
`index.html` のほうはデータを別ファイルから読むので、`file://` では動かない。
ローカルで配信版を見たいときは `npx serve dist` などで。

環境変数：

| 変数 | 用途 |
|---|---|
| `SITE_URL` | 公開先のURL。OGP・canonical・sitemap の絶対URLに使う |
| `ICONS=off` | アイテムアイコンを出さない（後述） |
| `ICON_BASE` | アイコンの配信元を自前のミラーに差し替える |

```bash
SITE_URL=https://fish.example.com node tools/build.mjs
```

## できること

- **トップ＝ダッシュボード** — 開いた瞬間に「いま窓が開いているヌシ」「★の魚の直近」「次のオーシャン便」「釣獲の進み具合」が出る
- **戻る／進む** — 画面の移動が履歴に積まれるので、ブラウザの戻るで元の一覧に帰れる
- **通知** — ★を付けた魚の窓が開いたら、音とデスクトップ通知で知らせる。タブのタイトルにも次の窓までの残り時間が出るので、裏に置いたままでいい
- **直感の手順** — 前提魚が要る魚は、①前提魚を釣る（エサとヒット秒数つき）②直感が付く ③本命を狙う、と手順に分けて出す
- **魚のリンク** — 詳細を開くと URL に `|fish=12345` が付く。そのまま貼れば相手も同じ魚が開く
- **地図** — 釣り場を開くと、その位置を切り出した地図が最初から見えている。押せば全体図に広がる
- **釣り場のツリー** — 拡張（新生／蒼天／紅蓮／漆黒／暁月／黄金）→ エリア → 釣り場 の3階層。どの拡張のものかは `TerritoryType.ExVersion` から機械的に決めている
- **ヌシ・オオヌシ一覧** — 並び替え（次回順／出現率が低い順／実装順／名前順）と、11 種類の条件で絞り込める。エサ・前提魚（直感）・出現率・ヒット秒数・実装パッチ・**次々回の日時**も同じ行に出る。拡張だけでなく **7.55 のようなパッチ単位**でも絞れる。釣り場名から地図が開く
- **釣獲フラグ** — 釣り場でもヌシ一覧でも「表示中を釣獲済みに」で一括登録できる。絞り込みの状態はブラウザに残る
- **★と釣獲フラグ** — ★はタイムライン用（URLに載る）、✔は釣った記録（ブラウザに保存）。どちらも**絞り込んだ状態のまま一括**で付けられ、「未釣獲のみ」で残りだけを表示できる
- **使い道** — 料理などの素材・収集品・グランドカンパニー納品の対象かどうかがタグで出る
- **ルアー** — モデストルアー／アンビシャスルアーが要る魚に、ゲーム内のアクションアイコンが付く。ヌシ一覧では「ルアー必須」だけに絞れる。いま窓が開いているものが先頭、次いで開始が早い順。拡張別・オオヌシのみで絞り込める
- **釣り場ビュー** — エリアから釣り場を選ぶと、釣れる魚・エサ経路・ET時間帯・天候条件・引き・フッキング・ヒットタイムが一覧で出る
- **出現ウィンドウのガントチャート** — その釣り場の条件付きの魚について、今後12時間の出現タイミングを実時間で並べる。天候はゲームと同じアルゴリズムで計算しているので予報は正確
- **今釣れるフィルタ** — いま条件が揃っている魚だけに絞る。行の左端が光る
- **横断検索** — 魚名・釣り場名・エサ名。エサで引くと「このエサで釣れる魚」が出る
- **魚の詳細** — 前提魚（漁師の直感）、伝承録、フィッシュアイ可否、次の出現ウィンドウ8件、釣れる場所の一覧

- **オーシャンフィッシングの運行表** — 次の便から48時間ぶん。寄港地は**通常と幻海流の両方**に飛べる。**その便で狙える称号と伝説魚・時間限定魚**を、推奨エサつきで各便に表示する（「伝説魚が狙える便」だけに絞り込める）
- **タイムライン** — ヌシ一覧の ☆ で選んだ魚だけを時間軸に並べる。12h / 24h / 48h / 7日 で切り替えられる。選んだ状態は URL に載るので、ブックマークすれば次も同じ顔ぶれ、そのまま人にも渡せる
- **ヒットタイム分布** — 釣り場の魚を同じ秒数軸に並べる。エサを切り替えられ、撒き餌あり／なしも比較できる。「6秒台で !! ならこれ」が目で分かる
- **表示言語** — 日本語 / English / Deutsch / Français。魚・釣り場・エサ・天候・航路の名前は4言語ぶん収録してある。検索はどの言語で打っても引ける
- **時間帯** — エオルゼア時間と現地時間を並べて表示。現地時間は FF14 のデータセンターがある地域（日本 / 北米西部・東部 / 欧州 / オセアニア）から選べる
- **フィッシュアイ** — トグルすると、時間制限が外れる魚を時間外でも釣れる扱いにして再計算する

`/` キーで検索窓にフォーカス、`Esc` で詳細を閉じる。

### ヌシ・オオヌシの判別について

ゲームデータに「オオヌシ」というフラグは存在しない。
コミュニティの定義（釣り手帳の並びで、ひとつの釣り場に大物が2匹いるとき後ろがオオヌシ）を
そのままルールにしてある。拡張ごとの数が実際と一致することを確認済み：

| 拡張 | 新生 | 蒼天 | 紅蓮 | 漆黒 | 暁月 | 黄金 |
|---|---|---|---|---|---|---|
| オオヌシ | 5 | 6 | 5 | 6 | 6 | 6 |

### 次回日時の計算

天候は8エオルゼア時間（1400 実秒）ごとに切り替わり、抽選はシード値から決定論的に決まる。
天候枠を跨いで走査し、枠と魚の有効時間帯を端数込みで正確に交差させている
（ET 23:30–01:05 のような 30 分刻みの魚も正しく出る）。

まず 60 日先まで探し、それでも窓が見つからない極端に稀な相手だけ 400 日先まで追う。
「リッチパース」（満ちた玄関・曇り→雨・ET16–18）のように次の窓が3ヶ月先という個体がいるため。

漁師の直感（前提魚）や伝承録が要る魚は、条件欄にその旨が出る。
時間・天候の縛りがない魚は「時間・天候は不問」と表示され、次回日時の代わりに常時扱いになる。

## 更新の頻度

`.github/workflows/build.yml` が**毎日正午（JST）**に走り、上流を取り直して公開まで通す。

ヌシの出現条件は上流の Fish Tracker が随時直しているので、日次で追いかける。
未確定だった条件が確定すれば、翌日には推定表示（⚠）が消えて本物に置き換わる。

窓の計算そのものはブラウザ側で実時間にやっているので、
データが同じなら再ビルドしなくても表示は常に正しい。日次更新が効くのは「条件そのものが変わったとき」。

パッチ直後など待てないときは **Actions タブ → Run workflow** で即座に回せる。

## パッチが来たら

```bash
node tools/import-bite-times.mjs --refresh
node tools/build.mjs --refresh
```

上流のコミュニティデータが更新されていれば、新エリアの釣り場と魚が自動で入る。

> **生成データはリポジトリに置いていない。** `data/fishing.json` と `data/bite-times.json` は
> 毎ビルドで作り直されるので `.gitignore` に入れてある。
> 以前はコミットしていたが、Actions が更新するたびに手元とぶつかっていたため外した。
> 手で足したい実測は `data/bite-times.manual.json` に書く（こちらは追跡される）。

上流の更新が追いつかない期間は、新しい魚は「条件未収録」として表示される。
名前と釣り場だけは Teamcraft 経由でパッチ当日にはだいたい入る。

## ヒットタイム

ヒット秒数はゲームのクライアントデータに存在しない。
FF14Angler が価値を持っていたのも、まさにここをプレイヤー投稿で何年も集めていたから。

いまはコミュニティ側にこの蓄積が公開されている。
`tools/import-bite-times.mjs` は Lodinn 氏が公開している釣り場別の集計 JSON を取り込む。
Fisher's Intuition Bot（`okuRaku/ff14-fishers-intuition-bot`）の `/biterates` が使っているのと
同じデータで、大元は Teamcraft の Allagan Reports に集まったプレイヤーの実測。

```bash
node tools/import-bite-times.mjs         # 全釣り場
node tools/import-bite-times.mjs 139 26  # 特定の釣り場だけ
```

釣り場IDもアイテムIDもゲーム内のものなので、こちらのデータとそのまま突き合わせられる。
元データは約 8 MB。要約と圧縮した分布だけを取り出して `data/bite-times.json`（1.25 MB）に書く。

### 取り込んでいるもの

| 項目 | 内容 |
|---|---|
| `lo` / `hi` | 撒き餌なしのヒット秒数レンジ |
| `clo` / `chi` | 撒き餌ありのレンジ |
| `rate` | そのエサでの釣果率（%） |
| `n` / `miss` | 釣れた回数と推定の空振り回数 |
| `h` / `ch` | ヒット秒数の分布。1ビン 0.5 秒 |

分布は `"開始ビン:値"` という文字列に詰めてある。値はピークを `z` とした base36 の1文字で、
JSON 配列で持つより 4 倍ほど小さい。

### レンジは分布から計算し直している

元データの `bitetime_low` / `bitetime_high` は外れ値をそのまま含んでいて、
「メルトールゴビー 0〜104 秒」のような使えない値になることがある。
分布がある場合は 2〜98 パーセンタイルを採り直している。
サンプルが十分な魚では元の申告値と一致することを確認済み。

### 副産物：引きとフッキングの補完

Lodinn 側は条件が未収録の雑魚についても引き・フッキング・スナッグを持っている。
突き合わせたところ引きは **一致 897 件、不一致 0 件**だったので信頼して取り込み、
**694 種**の引きを新たに埋めた。

フッキングの対応付けには注意が要る。Lodinn の `hookset` は
**1 = ストロング / 2 = プレシジョン**で、直感に反する並びになっている。
Fish Tracker と同じ魚で突き合わせて確認した。

| 魚 | Lodinn | Fish Tracker |
|---|---|---|
| スターフラワー | 2 | Precision |
| スピリット | 1 | Powerful |
| バスキングシャーク | 1 | Powerful |

### 検算：引きとフッキングの対応

「！ならプレシジョン、！！／！！！ならストロング」という経験則で全データを検算できる。

| 出所 | 種数 | 規則どおり |
|---|---|---|
| Fish Tracker 由来 | 821 | 90.4% |
| 実測統計由来 | 631 | 99.4% |
| 全体 | 1,452 | **94.3%** |

残る例外 83 件はすべて「！！！なのにプレシジョン」の 1 パターンで、
ザルエラ、オールドソフティ、ヌルヌルキングなど**ヌシに集中している**。
ランダムな誤りではないので、実際の仕様と考えている。

逆方向の例外（！なのにストロング、！！なのにプレシジョン）は 0 件。
この検算は取り込みの誤りを見つけるのに有効なので、上流のデータ構造が変わったときは
まずこれを流すとよい。

### 自分で足す場合

`data/bite-times.json` の `records` に直接書ける。キーは `釣り場ID:魚ID:エサID`。
サイトの魚詳細パネルに、その釣り場・その魚用のキー入りスニペットが出る。

```json
"139:12723:12708": { "lo": 11.5, "hi": 19.5, "n": 4059 }
```

> クライアント側の自動計測（パケットキャプチャやメモリ読み取り）は、
> FF14Angler の FF14AnglerRep や Teamcraft のオーバーレイが実際に使っている手法だが、
> スクウェア・エニックスの利用規約上はグレーからアウトの領域。採否は各自の判断で。

## 多言語対応について

**名前は4言語すべて収録している。** 上流のデータ（Teamcraft、Fish Tracker、datamining CSV）が
どれも en / ja / de / fr を持っているので、魚・釣り場・エサ・天候・伝承録・航路名は
そのまま4言語で出せる。検索も全言語を対象にしているので、日本語表示のまま英名で引ける。

**画面のラベルは日本語と英語のみ。** ドイツ語とフランス語を選ぶと、名前は現地語、
ラベルは英語になる。ラベルの翻訳が要るなら `app/index.html` の `STR` に
`de:` `fr:` を足すだけで、他は何も変えなくていい。

**説明文（釣り手帳のテキスト）は日本語と英語だけ。** 4言語ぶん持つとデータが 1 MB ほど増えるため。
必要なら `tools/build.mjs` の `SOURCES` に `de/FishParameter.csv` などを足せば拾える。

選んだ言語と時間帯は URL に載るので、`#nushi|l=en|z=naw` のような形で共有できる。
初回は `navigator.language` に合わせる。

## 銛とアイコンについて

XIVAPI v2 はビルド環境から直接叩けなかったが、同じシートが
`xivapi/ffxiv-datamining` に CSV でミラーされていたので、そちらから取っている。

**銛（スピアフィッシング）**は `SpearfishingNotebook` → `GatheringPointBase` →
`SpearfishingItem` と辿ると、釣り場と突ける魚の対応が全部出る。
釣り場IDは `GatheringPointBase` の行番号で、Fish Tracker 側の採番と一致するので、
既存の釣り場データとそのまま混ぜられる。**64 箇所・289 種**を収録。

**アイコン**は Teamcraft の `item-icons.json` が XIVAPI v2 のアセットパスを
そのまま持っているので、それを使う。全 2,620 種に付いている。

**釣り手帳の説明文**は `FishParameter.csv`（日本語版）と `SpearfishingItem.csv` から。
1,806 種に付いている。

## 用語について

日本語版の正式なアクション名は **ストロングフッキング**。
以前は「パワフルフッキング」と出していたが、これは英語の Powerful Hookset を訳したもので、
日本語版にそのアクションは存在しない（`Action.csv`: 4103 ストロングフッキング / 4179 プレシジョンフッキング）。

同じ理由で、画面の言葉づかいも見直した。

| 前 | 後 |
|---|---|
| 出現ウィンドウ | 釣れる時間帯 |
| 次の出現ウィンドウ | これから釣れる時間 |
| 次に釣れる | 次に釣れるのは |
| 次々回 | その次 |
| 400日以内になし | 400日先まで見つからず |

## 絞り込み

ヌシ一覧の操作は、並び替えのプルダウンと「絞り込み」パネルにまとめてある。
以前はボタンが3段に並んでいて、何が効いているのか分からなくなっていた。

絞り込める条件：

| 分類 | 選べるもの |
|---|---|
| 種別 | ヌシ / オオヌシ |
| 状態 | いま釣れる / ★ / 未釣獲 |
| 拡張 | 新生〜黄金（選ぶとパッチ単位の絞り込みが出る） |
| 引き | ！ / ！！ / ！！！（複数選択可） |
| フッキング | プレシジョン / ストロング |
| ルアー | 要る / 不要 |
| 伝承録 | 要る / 不要 |
| 直感 | 要る / 不要 |
| 天候 | 縛りあり / 不問 |
| 時間帯 | 昼 (ET6-18) / 夜 (ET18-6) |

効いている条件はバーの下にチップで並び、押せばその条件だけ外れる。
「絞り込み」ボタンには効いている数が出るので、閉じていても状態が分かる。

並び替えに **出現率が低い順** を足した。「めったに来ない相手から順に潰す」使い方ができる。

## 待ち時間との付き合い方

ヌシは数時間から数日待つ相手がいる。画面を見張り続ける前提にしないため、次の3つを入れてある。

**通知** — ヘッダーの 🔔 を押すとブラウザに許可を求め、以後 20 秒ごとに★の魚を見張る。
窓が開いた瞬間に短い音とデスクトップ通知が出る。同じ窓で二度は鳴らない。
音は Web Audio で合成しているので、音声ファイルは要らない。

**タブのタイトル** — ★があるとき、いちばん近い窓の状態が出る。
開いていれば `● 残り 12分`、まだなら `あと 2時間5分`。タブを裏に置いていても分かる。

**秒単位のカウントダウン** — 表示中の残り時間だけを毎秒書き換える。
1分ごとの再描画だと最大60秒ずれるが、23分しかない窓では致命的なので分けてある。

## モデストルアーとアンビシャスルアー

黄金のレガシーで増えた、アタリが来てから使って引きを変えるアクション。
これが要る魚は上流の Fish Tracker が `lure` として持っているので、そのまま使っている。
現在 12 匹（アンビシャス 9・モデスト 3）で、うち 6 匹がヌシ。

| ルアー | 魚 | 釣り場 | パッチ |
|---|---|---|---|
| アンビシャス | サンダードリフトトラウト | ドリフトダウンズ | 7.1 |
| モデスト | ムーンキャッチャー | 涙浮かぶ星池 | 7.1 |
| アンビシャス | ハーレクインクイーン | ザ・ノーアブル | 7.2 |
| アンビシャス | クレニシクラ・ミヤカ | デュースパン・バンク | 7.3 |
| アンビシャス | ウィンディ・ダトニオ | レイノード・ウィンド | 7.4 |
| アンビシャス | オーレーオーレーオーレー | チーワグー塩池 | 7.5 |

ヌシ以外の 6 匹（オルコミズガエル、ゾーゴーコンドル、クラウドワスプ、
ゴールデングルーパー、クレイランカープ、カッパーシャーク）にもバッジが付く。

パッチで増えても、上流が対応すれば日次のビルドで自動的に入る。

## 特殊コンテンツの釣り場

Teamcraft の釣り場データは、**特別なコンテンツの釣り場をすべて「ディアデム諸島」に
まとめてしまっている**（釣り場ID 10000 以降、mapId は一律 584）。
`data/spot-groups.json` の振り分け表で、その釣り場自身の地名ID（`zoneId`）を見て正しく戻す。

| 対象 | zoneId | 扱い |
|---|---|---|
| ドマ町人地 | 2507 | 紅蓮のリベレーター（上位階層も「ドマ町人地」） |
| エリュシオン | 4191〜4195 | 暁月のフィナーレ／ウルティマ・トゥーレ（オミクロン族の友好部族クエスト用） |
| ディアデム諸島・雲海 | 2258〜3533 | **収録しない** |
| コスモエクスプローラー | 5200〜 | **収録しない** |

ディアデムとコスモを外しているのは、**上流に釣りデータがまったく無いため**。
実測（ヒットタイム・釣果率）が 0 件、時間・天候の条件も 0 件で、
釣り場名と魚名しか出せない。名前だけ並べても使えないので `drop` に入れてある。

データが揃ったら `data/spot-groups.json` の `drop` から外すだけで復活する。

> 範囲判定を効かせるのは釣り場ID 10000 以降だけ。通常の釣り場にも同じ範囲の
> zoneId があるので、区別しないと漆黒や暁月の釣り場まで巻き込まれる。

## 条件が未収録のヌシについて

上流の Fish Tracker には `dataMissing: { weatherRestricted, timeRestricted }` という印がある。
「制限があるのは分かっているが、内容は未確定」という意味で、7.5 のオオヌシなどが該当する。

このサイトでは、そういう魚が**漁師の直感を要求する**場合にかぎり、
**前提魚の条件をそのまま実効条件として使う**。前提魚を釣らないと本命は釣れないので、
前提魚の窓がそのままボトルネックになるという理屈で、条件が複数あるときは
いちばん狭いものを採る。

例：スカイライトハート（セノーテ・ジャユンジャ）
前提はアントゥルーソーサー×1 + トゥルーソーサー×3。
アントゥルーソーサーが ET16–21・快晴→雨なので、これを実効条件として窓を出す。

推定であることは一覧に `⚠ 推定` として明示する。確定情報が上流に入れば自動で置き換わる。

## オーシャンフィッシングのエサ

上流の Fish Tracker はオーシャンフィッシングを扱っていないので、
この海域の魚には**エサの情報がまったく無い**。

そこで Lodinn の実測統計から、**釣果率がいちばん高いエサ**を選んで出している。
航路が使う 26 の釣り場（通常13＋幻海流13）はすべて実測が揃っているので、全魚に付く。

例：メルトール海峡南

| 魚 | エサ | 釣果率 |
|---|---|---|
| グラディウス | グールバラクーダ（泳がせ） | 38.0% |
| グールバラクーダ | クリル | 20.5% |
| グランドマーリン（幻海流） | ハイエーテルラウス（泳がせ） | 49.6% |

**泳がせが最有力のときは、その魚を釣るためのエサまで遡って `A ▸ B` の形で出す。**
たとえばグラディウスは「クリル ▸ グールバラクーダ」。竿に付けるのはクリル、
釣れたグールバラクーダを泳がせる、と読める。
泳がせでしか釣れず遡れない魚は、その魚の名前だけを出す。
実測由来のエサは色を変えてあり、ホバーすると根拠が出る。

**幻海流は釣れる魚が完全に入れ替わる。** ガラディオン湾沖合の通常10種と幻海流10種に
共通の魚は1匹もいない。データ上も別々の釣り場として持っているので、
運行表の寄港地から「幻」のバッジで切り替えられる。

## AutoHook からの補完

AutoHook（BSD 3-Clause）の `fish_list.json` と `fishing-sources.json` は、
魚影だけでなく**エサ・引き・フッキング・ヒットタイム**も持っている。
Lodinn の統計が届いていない範囲を埋めるのに使っている。

| 項目 | 補完数 |
|---|---|
| エサ | 575 種 |
| ヒットタイム | 1,515 種 |
| 魚影の大きさ・速さ | 289 種 |

**ディアデム諸島**はこれで復活した（22 釣り場）。以前は釣りデータが 0 件で
名前しか出せなかったが、AutoHook が 15 箇所ぶんのエサとヒットタイムを持っていた。

**コスモエクスプローラー**はどちらのデータ源にも無い。
Ice's Cosmic Exploration も調べたが、そちらは釣り部分を AutoHook に委ねる構造で
独自の魚データを持っていなかった（リポジトリも非公開）。
そのため、**情報が何も無い釣り場は自動で除外**する仕組みを入れてある。
魚に条件もエサも実測も無い釣り場は、名前だけ並べても使えないため。

## 伝説魚と稀少魚

`FishParameter.OceanStars` が 5 の魚がちょうど 13 匹あり、幻海流の寄港地ごとに 1 匹ずつ対応する。
これが伝説魚で、海域と必要な時間帯まで確定している。

**稀少魚**（通常海域の直感魚）はゲームデータでは伝説魚と区別が付かない
（どちらも OceanStars 4/5・IsHidden）。そこで「通常海域にいて漁師の直感が要る魚」で判定している。

### 直感条件

ゲームデータに無いので `data/fish-conditions.json` に手で入れている。**全13海域ぶん揃っている。**

|---|---|---|---|
| ガラディオン湾沖合 | ドランカードフィッシュ | ソティス | 8秒 |
| メルトール海峡南 | リトルリヴァイアサン | コーラルマンタ | 15秒 |
| メルトール海峡北 | 海の流星 | エラスモサウルス | 15秒 |
| ロータノ海沖合 | シーサバトン | ロックスケイル | 15秒 |
| シェルダレー諸島沖合 | シェルダレージオード | ハーヴグーヴァ | 15秒 |
| ロズリト湾沖合 | ギンコフィッシュ | プラコドゥス | 45秒 |
| 緋汐海沖合 | ベアフェイス | オーシャントード | 15秒 |
| セイレーン海沖合 | ダスキーシャーク | タニファ | 15秒 |
| クガネ沖合 | 水引魚 | 瑠璃龍 | 15秒 |

稀少魚の直感はどれも 60 秒。伝説魚は 8〜45 秒とばらつきがあり、
**ソティスの 8 秒**が最短で、直感が付いた瞬間に投げないと間に合わない。

前提魚のヒット秒数は実測データから自動で付くので、魚の詳細では
「①前提魚を釣る ②直感が付く ③本命を狙う」の手順表になる。

ヌシ・オオヌシの直感時間は上流の Fish Tracker が持っているぶん（24 種）が入る。
陸のヌシは 35 秒〜1400 秒と幅が広い。

### 照合について

取り込む前に、**魚名が実在するか**と**その釣り場にいるか**を必ず突き合わせている。
今回の 24 種はすべて一致し、引きの強さも記事の記述と合っていた。

> 以前、生成AIが出力した「伝説魚一覧」を取り込もうとして照合したところ、
> ストーンスケール、ハーフタートル、オファニムといった**実在しない魚**が半数近く含まれていた。
> この手の一覧は必ずゲームデータと突き合わせてから入れること。

## 便ごとの称号

`IKDFishParam` が「どの魚がどのボーナス条件に数えられるか」を持っている（78 匹ぶん、12 条件）。
3 つの寄港地（通常＋幻海流の 6 か所）を合計し、同じ魚は一度だけ数えて集計する。
寄港地の時間帯に合わない魚は除く。

そのうえで、**その称号にとって対象魚がいちばん多い航路にだけ**「狙える称号」として出す。

## オーシャンフィッシングの運行位相

便は **UTC の2時間ちょうどごと**に出て、144便で12日かけて一周する。
どの便がどの航路かはゲームの `IKDRouteTable` に載っているが、
「いまが表の何番目か」という位相だけはゲームデータから読み取れない。

```
chunk = floor(unix秒 / 7200)
航路   = IKDRouteTable[(chunk + 41) % 144]
```

この `41` は、コミュニティの独立した2実装が持つ運行表を、
ゲームの `IKDRouteTable` と突き合わせて求めた。

| 実装 | 自前のオフセット | ゲーム表との回転量 | 合成 |
|---|---|---|---|
| proyebat / FFXIVOceanFishingTimeCalculator（藍） | 85 | 100 | **41** |
| momokotomoko / StreamDeck プラグイン（紅） | 89 | 96 | **41** |

出自もオフセットも回転量も違う2つが、ゲームの表に対しては揃って 41 になる。
これで位相は確定と見てよい。ズレたときは `tools/build.mjs` の `OCEAN_PHASE` だけ直せばいい。

寄港地は `IKDSpot` の `SpotMain` / `SpotSub` が、そのまま通常の釣り場IDと幻海流の釣り場IDになっている。
時間帯コードは `1=夜 / 2=昼 / 3=夕`（プラグイン側の全12航路の寄港順と突き合わせて確認済み）。

## 既知の穴

| 穴 | 状況 | 埋め方 |
|---|---|---|
| オーシャンの釣果点・多重フッキングの匹数 | どのデータ源にも無い | `data/ocean-notes.json` に手で書けば出る |
| オーシャンの伝説魚に必要な「漁師の直感」の前提魚 | 未収録。ゲームデータにも借りている一覧にも入っていない | 手で入れるか、上流に情報が増えるのを待つ |
| 幻海流トリガーの魚 | 未判別。スペクトラルメガロドンなどを他の魚と区別できていない | 同上 |
| オーシャンフィッシングの伝説魚をヌシ一覧に出していない | 航路と幻海流の抽選に依存するので、時間・天候の窓としては表現できないため | 釣り場ページには載っている |

## 公開する

**まだ何も用意していないなら [PUBLISHING.md](PUBLISHING.md) を見てほしい。**

### Cloudflare Pages（おすすめ）

2回目以降の表示が体感で変わる。

2. ビルドコマンド `node tools/import-bite-times.mjs && node tools/build.mjs`
3. 出力ディレクトリ `dist`
4. 環境変数に `SITE_URL` を設定

### GitHub Pages

`.github/workflows/build.yml` がそのまま使える。
`SITE_URL` を自分のURLに書き換えて、リポジトリの Settings → Pages で
Source を「GitHub Actions」にするだけ。毎週月曜に上流データを取り直して再公開する。

`_headers` は効かないのでキャッシュは短め。表示は問題なく動く。

### Netlify

ビルドコマンドと公開ディレクトリは Cloudflare Pages と同じ。`_headers` も効く。
